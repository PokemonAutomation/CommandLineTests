# Capture Card Color Calibration

Each user runs the automation program through a different capture card, OS and Switch video setting.
A visual detector that passes on one screenshot can fail for a user whose card brightens, darkens or over-saturates the image.

This folder collects screenshots from devs and friends to sample and compute color distortions and  
the scripts here measure how much known capture card / OS / Switch setting combinations change colors.
Then any test screenshot can be re-colored to look like it came through other setups,
so **one test image can cover more measured range of color settings**.

## Folder Overview

```
CaptureCardCalibration/
    Switch1/
        CFW-BrightBG-Up.png        <- "CFW" images are references: undistored by capture card
        CFW-BrightBG-Down.png
        Kuro-Win-MYPIN-Up.png      <- Calibration images come in pairs ("Up" & "Down")
        Kuro-Win-MYPIN-Down.png
        ...
    Switch2/
        ...
    ...                            <- scripts, JSONs and generated png
    details/                       <- not in git: contributors, label reasoning, measurement details,
                                      test image source tracing
```

Every image is captured at the Switch user icon **Edit Background** color picker screen.
"Up" is scrolled to the top (red to green rows) and "Down" is scrolled to the bottom (blue to blue-gray rows),
which gives 60 flat color patches per pair. The palette is the same on Switch 1 and Switch 2.
We use the CFW pairs are the reference for both consoles.

| File | Purpose |
|---|---|
| `color_profile_labels.json` | Hand-maintained map from each distortion label to its calibration image pairs. For ease of use we give a label like `Win-CheapCard-GreenShift` for each setting.|
| `measure_capture_card_colors.py` | Vibed by Claude. Reads the calibration images (see below), fits one color transform per distortion label, writes the transform JSON files and a swatch report. |
| `simulate_capture_card_colors.py` | Vibed by Claude. Applies the measured distortions (or random mixtures of them) plus optional blur / chroma / JPEG / noise stages to any test image. Used for testing and prototyping distortion simulation. |
| `color_profile_to_transform.json` | Generated by `measure_capture_card_colors.py`: mapping from label -> color disortion transform matrix. `simulate_capture_card_colors.py` and the C++ test framework read them to apply distortion. |
| `color_profile_extremes.json` | Generated by `measure_capture_card_colors.py`: the script picks several distortion settings from the calibration images that are the "extreme" cases of distortion that should be the test targets for visual detection. |
| `color_profile_report.png` | Generated by `measure_capture_card_colors.py`: a color overview picture ("swatch") to visualize the range of color distortion across calibration images. |
| `test_image_labels.json` | (work in progress) maps each test image path to the label of the capture setup it came from (or Unknown), so test code can undo that setup's distortion before re-coloring the image with the extreme distortions to widen its test range. |

Python lib requirements: `numpy` and `Pillow`.


### Distortion labels

Labels are defined in `color_profile_labels.json`.

- `Reference` lists the undistorted pairs that define the true colors.
- Naming convetion: `<OS>-<Card>-<AdditionalAttributes>`, 
- All calibration image pairs under one label are used together to compute their average distortion
  in `measure_capture_card_colors.py`.The script warns when a pair's colors are more
  than RMS 3 from its label's average, which means it measured a different distortion and needs
  its own label.
  The script also lists labels that measure practically the same distortion (RMS 2 or less) and
  should ideally be under the same label.
- When the same OS and card give different results, the label should give a suffix that describes the
  difference, e.g. `-GreenShift` or `-HighContrast`.
- The console model itself doesn't change colors much: the same card measured on a Switch 1 and a
  Switch 2 agrees within RMS 0.8 (`Win-CheapCard`) and 1.3 (`Mac-Mirabox`). But 4 of the 6 Switch 2
  units calibrated so far add a **green shift**: in saturated colors, magentas and reds lose green and
  greens gain it, by up to about 40 levels. The pattern is the same on all four (correlation
  0.91-0.99) whatever the card, so it is probably a console setting. Those calibrations get
  `-GreenShift` labels.

To add a new capture card: take the Up and Down screenshots through it, put them in the folder for
the console, add the image pair path to `color_profile_labels.json` under an existing or new label,
and rerun the measurement script.
The script warns about images in the console folders that the manifest doesn't list.
The console's light/dark theme, language, avatar and cursor position don't matter.
Only the center 40% of each patch is sampled, so the cursor outline and color bleed at the patch edges
are left out. Images must be full 16:9 frames. Run with `--debug-dir` to check where the sample squares
landed.


## Measuring

```bash
python3 measure_capture_card_colors.py            # defaults to the folder the script is in
```

Outputs, written to the calibration folder:

- `details/calibration_file_details.json` (not in git): reference colors; for each distortion label,
  its calibration pairs and how far each is from the label's average, the captured colors, the
  fitted transform, error statistics and YCbCr parameters; the min/max of every patch over all
  labels; and the extreme labels with the corners they cover.
- `color_profile_report.png`: one row per label. Each swatch shows the captured color (top)
  over the model's prediction (bottom).
- `color_profile_to_transform.json`: every distortion label's 3x4 transform, for test code to undo the
  distortion of the setup a test image was captured with. `Reference` maps to the identity.
- `color_profile_extremes.json`: the extreme labels for the C++ test framework to load and augment
  image tests with.

Both transform files are a plain map from label to a 3x4 matrix `[M | b]`, one row per line:

```json
{
  "Win-MYPIN": [
    [0.98086, -0.05106, -0.00127, -4.94545],
    [0.03679, 0.89118, -0.00783, -3.77839],
    [-0.00877, -0.06012, 0.99703, -7.10424]
  ]
}
```

A label's transform turns the true color into what that setup captures, with RGB in 0-255:

```
captured = clip(M @ rgb + b, 0, 255)      R' = m00*R + m01*G + m02*B + b0, and so on
```

Each row gives one output channel: three weights for R, G, B, then the offset `b`. To undo a test image's
setup, invert its transform as a 4x4 matrix (add the row `[0, 0, 0, 1]`); to simulate another setup,
apply that setup's transform afterwards. Both steps combine into one 3x4 matrix.

### Extreme transforms

To keep C++ tests fast, test images aren't re-colored with every distortion setting.
Instead they use a few extremes, chosen along the three ways real cards differ:

| Axis | Low end | High end | Measured as |
|---|---|---|---|
| shadows | crushed | raised | average luma change of grays 0, 16, 32 |
| highlights | dim | bright | average luma change of grays 192, 224, 255 |
| saturation | low | high | average Cb/Cr gain in BT.709 YCbCr |

Each axis is scaled to 0-1 over the measured cards. For each of the 8 corners of that box, the
extreme is the card that goes furthest toward the corner (the highest `(corner - 0.5) . position`).
A card already picked for another corner is preferred when it scores within 0.2 of the best, so
similar cards don't both get picked.

Why not interpolating or extrapolating existing distortion transforms: that could create unrealistic
transforms that we shouldn't run tests on.


## Simulating

```bash
# One variant per measured profile, plus a contact sheet:
python3 simulate_capture_card_colors.py test.png --out-dir out/ --sheet

# The extreme transforms:
python3 simulate_capture_card_colors.py test.png --out-dir out/ --extremes --sheet

# 20 random mixtures of the profiles, 20% stronger than measured, with MJPEG-like artifacts:
python3 simulate_capture_card_colors.py test.png --out-dir out/ --random 20 --extrapolate 1.2 \
    --chroma-subsample --jpeg-quality 80 --noise 1.5
```
